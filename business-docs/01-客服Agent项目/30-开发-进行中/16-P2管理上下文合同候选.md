## 1. 问题、复用与所有权

桌面新上传需要 `IntakeReceive.sourceVersion/baseReleaseId` 及贡献人声明。现有来源目录提供来源版本，现有认证会话提供产品 userId；两者不能推导当前全局发布指针或内容域 principalId。不得通过公告/旧 hydrate 的副作用取得管理基线，也不得将 userId 当作 principalId。

核对后确认，**参与人选择合同已经存在**：OpenAPI 1.16 起的 `GET /v1/intake/principals` 与 `IntakePrincipalPage` 已包含 `sourceId/purpose/limit/cursor` 和主体 ID、展示标签、事实版本/期限、启用状态。产品 `951269e` 有生成类型，尚无该路由/服务接线。本次只复用它，不增加第二目录 API、人员表或展示名真源；§3 明确合成接线的边界。

治理仓拥有本候选及生成源；既有身份模块拥有会话到主体的已确认绑定与登记标签来源；内容 API 拥有来源授权、当前发布指针读取、分页投影和提交时重新校验；Main 拥有选中来源、上下文与目标参与人、取消代际和恢复用原操作输入；renderer 只提交选择意图。既有来源映射、`content_current`、主体事实、候选 key 保持唯一真源。

比较两个边界：

| 方案 | 调用方负担和信息暴露 |
| --- | --- |
| A：扩充全局授权/来源目录，所有菜单读取都返回发布指针与人员映射 | 将上传前置事实混入坐席发现流程，扩大可见范围，并使目录分页承担额外一致性义务 |
| B：按来源 import 权限增加最小管理上下文，人员仍使用现有选择合同 | 只有实际准备上传时读取六个必要字段；无新权限模型、目录快照、展示名或租约状态 |

选择 B。新机器产物只增加一个 GET 和一个响应 schema；1.18 的全部 path/schema 与 schema.v1.21 原字节不变；旧 profile 的历史导出能力保留。现有合同支持的来源确认、审批状态、质量检查、发布、报告保存可以继续独立开发。

## 2. 最小管理上下文

`GET /v1/intake/sources/{sourceId}/management-context`，使用 ProductSession。唯一参数是符合 IntakeId 的 sourceId；未知/重复 query、GET body 失败关闭，不接受 actor/userId/principalId、base 或店铺自报输入。

| 字段 | 真源与语义 |
| --- | --- |
| `sourceId` | 与已授权路径严格一致 |
| `sourceVersion` | `sources.current_mapping_version`；与 IntakeSource.version / IntakeReceive.sourceVersion 同义，不另造序号 |
| `baseReleaseId` | 唯一 `content_current` 的 release ID；尚无发布时为 null，不推测最近候选、不泄露该发布正文 |
| `principalId` | 根据认证会话 userId 从现有已确认绑定解析出的内容主体 ID，不能回显客户端声明 |
| `factsVersion` | 该认证主体当前事实版本；不代表目标参与人的事实 |
| `validUntil` | 认证会话、主体事实和本来源 import 权限三者的最早截止；不承诺该时刻之前不会撤权或变更 |

读取复用现有事务、身份和授权谓词，在同一受保护读取中获取会话、当前事实/权限、来源映射和发布指针。跨 tenant/app、未知来源与无 import 权统一返回相同404；单有查询、管理、审核或发布权限不能读取。必须在操作结束时重验读取到的截止，不因慢查询延长权限。

它是准备信息，不是提交票据；没有授权续期、entitlement、lease、ACK、last-seen、公告确认或远端飞书刷新副作用。成功响应设置 `Cache-Control: no-store`，上限65,536字节；内部超限不返回部分对象。Main 不在 renderer 中暴露凭据或可指定身份的入口。

新创建候选前重新取得上下文；若有意修订既有候选，使用候选列表返回的确切 `expectedPriorKey`。receive 继续在提交事务重新校验身份、权限、来源版本和 base；并发发布导致 `BASE_CHANGED`，变更材料不能复用旧操作 ID。提交结果不明时保留原 ID 和完整原载荷，查询/重试原操作，不先替换 base 后盲目重放。上下文过期或撤权后不能继续展示为可操作授权；切换来源/会话和取消都应清除旧状态并拒绝迟到响应。

沿用 IntakeError：非法输入400、会话无效401、资源无权/不存在404、版本/事实冲突409、过载503；不引入新错误码或泄漏提供方原文。真实飞书认证与组织刷新继续由其专项批准管理。

## 3. 复用已有参与人选择

调用 `GET /v1/intake/principals?sourceId=…&purpose=contributor&limit=…&cursor=…`。上传使用 contributor；grant-recipient 留给已有分配流程，不把首次授权对象必须已有业务 grant 当作前置条件。机器字段和既有授权语义不改写。

- **可见范围：** 每页先重新确认会话及目标来源的相应权限。contributor 要求该来源 import；grant-recipient 要求该来源分配资格。只从相同 tenant/app 的已确认登记主体投影；不按目标已有业务 grant 过滤贡献人，也不扩大到全公司其他 app。无 scope 权拒绝整页。
- **身份与资格分离：** 贡献人可已禁用或离职，只要身份仍可确认；选择不使其成为执行者，不授予操作资格。`validUntil` 对目标表示该条事实的截止，不让过期/禁用事实变成当前授权。授权接收人仍要求当前启用、岗位适格和新鲜事实；提交由原授权事务以事实版本 CAS 重验。
- **标签真源：** `displayLabel` 只用于选择，不能用于同人识别或回传身份。在本轮合成宿主中使用明确登记的合成标签，按既有 principal ID 绑定；缺失或无权读取标签时失败关闭，不从邮箱/提供方 ID/岗位猜姓名、不增加可编辑标签表。当前 DDL 没有姓名/标签列，真实显示名应来自获准身份提供方的受控投影，仍需真实目录专项批准；本页不授权读取真实员工。
- **分页与取消：** limit默认50、最大100，cursor最长512字符。按 principal ID 的 C/ASCII 顺序 keyset 分页，每页至多扫描 limit 条登记事实（可另查1条判断后续），每条整项返回；grant-recipient 过滤后可以空页仍有 nextCursor，客户端须继续，不能把空页当结束。下一游标推进到最后扫描项，禁止重复同游标。每页响应上限262,144字节；不截断标签或默默省略选择对象。取消由 Main/HTTP abort 实现，服务端读取有界且取消不写业务状态。
- **游标不是授权：** 完整性保护并绑定当前会话、tenant/app、source、purpose、limit、调用者事实/权限版本、位置和最早截止；每页重新验权。换会话/范围、撤权、事实过期、游标篡改或服务重启均失败关闭，不能带出旧页。目录不承诺跨请求同一时刻快照，不另建全局目录版本；目标注册/事实变化按当前页读取，最终声明入候选前重验全部目标身份。
- **声明：** 整理人与全部实际改稿人使用所选 principal ID，纯本人制作也须显式列本人。服务器加入认证上传者、按现有同人规则归一，冻结完整 contributors；查不到的参与人先登记，不能省略。选中目标不替代会话 actor；更换贡献人须新材料版本。

产品接线时复用现有主体/授权模块，不把本页的运行义务当作已有代码。1.16目录合同已经可以独立实施；新管理上下文接入按本次批准和版本化 intake 推进。未来真实组织目录授权不由合成标签 fixture 通过代替。
