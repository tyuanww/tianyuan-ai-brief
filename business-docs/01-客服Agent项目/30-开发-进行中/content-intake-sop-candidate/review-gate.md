> 状态：`DRAFT · REVIEW INPUT ONLY`

本记录把 `sop-xlsx-v1` 格式候选与媒体运行边界候选交给治理评审。它只列出进入正式冻结、导出和产品 intake 前必须作出的合同决定，不代表这些决定已经批准，也不打开生产 runner。

## 冻结前必须由所属治理仓确认的决定

这些项目已有候选占位，但不能由实现者默认决定：

1. **正式合同版本**：沿用哪个已冻结的 OpenAPI/schema 基线，或批准新的版本号；生成器输出必须与候选路径逐项对应。
2. **迁移编号与所有权**：为三张 `sop_*` 表分配正式迁移编号，确认回退、外键和权限由哪个迁移/函数所有者维护；候选 SQL 仍保持 additive、不可直接安装。
3. **附件保留与回收**：批准 staged/adopted/released/discarded 的保留期限、回收触发和未知提交保护窗口；在仍被候选、发布或租约引用时不得删除。
4. **对象存储安全配置**：确认实际供应商、私有桶/路径、服务端加密、短时预览代理和审计字段；客户端继续只拿 opaque `mediaObjectId`。
5. **来源绑定**：确认正式 `sourceId` 与店铺/资料域的绑定记录及维护责任人；候选不能用真实店铺名、真实飞书 URL 或凭据代替登记。
6. **运行启用条件**：确认生产 runner 的 profile、受限数据库角色、HTTP factory 和合成回环验收证据；在前五项和产品 intake 回执完成前保持 `productionConsumerReady=false`。

## 通过冻结、导出和 intake 的最小证据包

- 评审记录逐项给出上述六项的批准值和责任人；未决定项继续保持候选状态。
- 生成器从批准源文件产生版本化 OpenAPI、schema、安装/权限清单及 SHA-256；禁止手工复制候选 JSON/SQL 作为正式合同。
- 正式 SQL 在合成 PostgreSQL 上完成安装前后校验、外键/回退/权限测试，并记录 `COMMIT_UNKNOWN` 与失败回收的实际断言。
- 导出回执锁定合同成员哈希；产品仓 intake 只接收该回执指向的字节，未接收的候选不得进入 runner。
- intake 后仍先完成合成的上传→检查→确认发布→第二坐席文字查询/图片预览/复制回环，再讨论真实资料和设备验收。
