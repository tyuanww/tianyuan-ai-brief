## 1. 差集与所有者

产品侧已完成隔离合成 `issueEntitlement / snapshot`，实测暴露两项 formal wire 缺口：选择只由内部 adapter 注入，不能通过正式资格请求传输；每类引用允许 100 个，但快照 vocabulary 整页最多 100 个。前序规范为 [13-P2资料接入合同候选](13-P2资料接入合同候选.md)，本页只拥有本次增量，不重述原权限/审批/发布合同。

治理仓拥有新 OpenAPI 1.17.0 / schema.v1.21 候选及标准限制；产品 API 拥有认证、选择规范化、资格签发与逐页核验；现有身份模块仍拥有会话。Main 独占本机当前店、选择、回调代际、正文/复制动作失效；renderer 只提交选择意图，不提供身份或会话凭据。

比较 A 每页重传可变选择，B 独立全局当前选择表，C 不可变资格上下文。沿已确认的最小接口采用 C：复用原 entitlement 的 shop/contextGeneration 和既有 session，仅补其私有会话键及两组选择；分页不重传，也不依赖服务进程内状态。没有新身份服务、发布指针或审批引擎。

## 2. 最小 wire 与行为

- `POST /v1/intake/entitlements` 增加必填 `productIds`、`scenarioIds`，每类 0–100 个唯一 IntakeId。空集合明确只匹配该类无限制条目；无默认全量。原 shopId/contextGeneration/releaseId 必填语义保留。
- API 在签发前批量核验词项 kind、active、tenant/app/brand/domain、品牌通用或当前店适用性。选择不能增加来源权限，也不能把品牌词项当成品牌来源授权。未知、跨租户/店铺或 kind 不匹配返回同一脱敏 NOT_FOUND；数组重复/超限/非法标识/未知字段为 VALIDATION。排序用 C/ASCII，无大小写折叠或名称猜测。
- 会话仅由认证层解析成 `backend_identity.sessions.token_hash`，属于服务器私有存储键，禁止出现在请求 body、响应、日志或 renderer。登录 user/role 仍不替代业务授权。
- `GET /v1/intake/snapshot` 参数仍只有 entitlementId/cursor/limit。通过资格读取持久的 shop/contextGeneration/选择；每页还必须将当前认证会话与绑定精确匹配，并核验会话存在、当前用户绑定、启用、未撤销及未过期，之后执行原权限/来源/审批/期限门。响应、游标不携带会话键。
- 换店/选择由 Main 增加本机代际、取消旧请求和立即撤销旧结果动作；迟到回调不得恢复旧正文。代际不是权限。API 不维护全局“当前选择”，另一个仍有效资格在原授权及期限内的可读性，不代表 Main 可在新上下文接受它。
- 新签/续签仍只允许 current，额外把产品会话 expires_at 纳入原最早截止。同一资格不续命；丢签发响应可重签，旧资格不延长。正常发布与真正撤权/审批撤销继续分开。

## 3. 持久边界与兼容

新 `content_intake.entitlement_contexts` 为一份 entitlement 的 1:1 不可变上下文，保存会话私有键、按 C/ASCII 排序去重的 product_ids/scenario_ids。不重复保存店铺、代际或到期时刻。创建门校验会话所属 user、启用/撤销及包含资格有效期，并对会话/身份行取共享锁；退出/禁用更新须等本次签发事务结束。延期约束要求新资格与上下文在同一事务提交，缺一即整批回滚。

会话表的短期清理不应被历史资格阻塞，因此上下文不对 sessions 建永久 FK；创建时校验绑定，消费时必须重新 JOIN 当前会话，缺行/退出/禁用/到期立即拒绝。API 持有会话共享锁核验直到本次资格/页面事务完成，并在最后提交点重验最早截止。存储约束不代替会话认证或权限查询。

前序已有 entitlement 不做猜测回填：没有上下文的资格在新版 API 一律拒绝并重新申请。新 API 与新迁移须在受控接入中成对启用；未 intake 的产品继续消费旧锁。本候选只追加 reference DDL，产品的 0022–0024 私有 overlay 不导回治理仓，未来由产品生成器在保留现有 24 段 checksum 的前提下追加迁移。新 schema/table/function 仍无应用角色授权。

## 4. 单条与分页预算

保持快照整页 vocabulary=100。启用条目的 productRefs + scenarioRefs 总数最多 100，使用标准 JSON Schema 条件表达所有拆分边界，无私有关键字；生产者 `IntakeEntry` 与消费者 `IntakePublishedEntry` 同约束。每类上限仍为 100，100+0、80+20、0+100 都合法，100+1 拒绝。重复/跨 kind 引用仍由原规范校验。

历史超限条目允许显式 disable，不能重新 upsert。历史候选发布、base 合并和 snapshot 遇到无法分页的启用条目须 FILE_LIMIT 失败关闭，不能截断或跳过；需纠正候选。多条累计超限提前分页，游标用实际末条，引用的原 displayVersion 完整保留。审批/材料版本和缺行保留规则不变。
