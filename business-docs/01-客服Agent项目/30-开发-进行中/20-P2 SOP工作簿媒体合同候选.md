# P2 SOP 工作簿媒体合同候选

> **状态：** `DRAFT · NOT FROZEN · NOT EXPORTED · NOT INTAKE · SYNTHETIC DEVELOPMENT ONLY`

本候选把首期带图片的 SOP 工作簿纳入现有资料接入链的格式合同。它只定义输入格式、行文字、内嵌图片、版本和幂等语义；不改已经冻结的 FAQ／CSV、运行接入或旧 `ops-loop` SOP 库合同，也不授权真实飞书、真实客户资料、生产数据库或生产 runner。

2026-10-10 的[业务方案](../90-评审/2026-10-10_SOP与四表业务方案选定.md)只选定业务规则，不改变本候选字节，也不把本候选升为正式合同。

## 1. 适用范围与边界

首期试点仍是 Menokin。来源事实、店铺／品牌范围和上传资格由已有服务端登记与权限链提供，工作簿不能自行扩大范围。范围确认人沿用当前决定，由项目负责人本人确认；本候选不记录姓名、凭据或真实来源链接。

本候选只覆盖内容接入链的 SOP XLSX 输入。FAQ、售前、售后和活动继续使用已冻结的 `faq-p1.1` XLSX／`faq-csv-v1` CSV 合同；非 SOP 文件中的图片或附件继续按各自合同处理，不因本候选获得媒体语义。现有 `/v1/sop/import` 的 `ops-loop` CSV 树写入合同保持独立，不能用它替代本候选。

六个工作表全部纳入，名称同时作为分类值和查询筛选值：

| 顺序 | 工作表／分类 |
| --- | --- |
| 1 | `过敏流程SOP` |
| 2 | `少错破SOP` |
| 3 | `品质售后SOP` |
| 4 | `税收相关规则` |
| 5 | `品牌对接资源汇总` |
| 6 | `长痘痘SOP` |

缺少任一工作表，或多出未登记工作表，整批拒绝。工作表名只作为结构和分类，不代表已读取或批准了工作表正文。

## 2. 输入上下文与版本

服务端从已登记来源上下文填入 `sourceId`、`brandId`、`scope`、`scopeKind` 和六个 `selectedSheets`；客户端或文件内容不能提交另一个范围来取得权限。机器候选见 [`content-intake-sop-candidate/protocol.json`](content-intake-sop-candidate/protocol.json)。

版本按以下顺序确定：

1. 扫描每个工作表的表头，精确识别 `版本` 或 `版本号` 列；读取该列第 2 行起的非空纯文本值；
2. 全部非空版本值必须相同，作为候选 `version`；冲突整批拒绝；
3. 没有非空版本值时，使用原 XLSX 字节的 SHA-256 作为 `version`。

原字节 SHA-256 始终单独保留为完整性证明，即使版本列存在也不能省略。相同 `sourceId + version` 的导入必须幂等，重放返回已有结果，不生成第二份候选；相同来源的不同版本才创建新候选。不同来源即使版本字符串相同也不能互相重放。

## 3. 行文字与图片归属

每个工作表逐行读取，按列顺序收集所有非空文字；保留单元格内换行，并用一个换行连接同一行的多个单元格。纯文字和富文本的文字部分可读；公式、日期、数值或其他非文字单元格属于 `NON_TEXT_CELL`，不得猜测或隐式转换。行 ID 为 `sop:<工作表名>:<行号>`，分类保留原工作表名称。

只接受工作表内嵌的 PNG、JPEG、GIF。图片从原字节提取为系统附件候选，记录附件 ID、工作表、行号、列号、MIME、字节数和图片 SHA-256；同一行多张图片全部关联到该行，顺序按工作表图片出现顺序保留。外部超链接只允许作为文字标签读取，解析器不得访问、下载或解析外部地址。

图片是辅助说明，答案正文必须由同一行文字给出。图片所在行没有可用文字时，整批拒绝并返回 `IMAGE_WITHOUT_TEXT` 及工作表、行号；不能把图片 OCR 成答案，也不能只保留图片而放行。非 SOP 图片或附件不进入本候选的媒体结果。

## 4. 失败、完整性与容量

阻断错误包括：`INVALID_CONTEXT`、`MISSING_SHEET`、`UNKNOWN_SHEET`、`NON_TEXT_CELL`、`MEDIA_UNAVAILABLE`、`MEDIA_LIMIT`、`IMAGE_WITHOUT_TEXT`、`VERSION_CONFLICT`、`EMPTY_DATA`、`INVALID_XLSX` 及现有归档预算错误。只要存在阻断错误，返回空 `rows` 和空 `attachments`，不能部分发布。

候选沿用现有资料归档的合成预算：原文件最多 10 MiB、展开内容最多 50 MiB、最多 512 个 ZIP 成员、最多 5,000 行、最多 32 列、最多 200,000 个单元格、单元格最多 32,767 个字符、累计规范文字最多 3,000,000 个字符、最多 100 张图片、单张图片最多 5 MiB、图片总字节最多 20 MiB。上述是候选校验上限，不是生产容量承诺；生产 runner 必须在独立进程／资源边界内复用或重新批准这些限制。

宏、活动内容、外部资源、路径穿越、损坏 ZIP、模糊坐标和预算超限都 fail-closed。解析器不执行公式，不跟随外链，不把客户端 MIME 或文件名当作格式证明。

## 5. 后续接线条件

本候选通过格式审阅后，才可另行起草版本化的 HTTP／存储增量。下一份机器合同至少要说明：原字节与附件对象的持久绑定、候选 material 的 SOP 行和附件引用、`sourceId + version` 幂等键、上传／检查／确认发布的四岗权限、失败回收、发布后查询预览，以及另一客服复制时只复制文字答案的行为。它还必须说明旧目录只读保留、明确认领后新目录接管和历史版本保留，不得在本候选里偷渡自动同步或真实目录。

生产 runner 只能在以下条件全部满足后接入：机器合同获批准并冻结、导出和产品 intake 有独立回执、runner 的进程隔离／取消／输出校验通过、合成上传→检查→二次确认发布→另一客服查询复制闭环通过。当前这些条件均未满足，本候选不能被写成生产能力。
