## 2. 三项旧语义的替换范围

| 冲突 | 新路径规范 | 旧路径兼容 |
| --- | --- | --- |
| agent/coach/owner 与精确授权 | 登录 actor registry 保留；当前有效组织事实 ∩ 精确部门/岗位上限 ∩ 业务 grant。不同店铺显式分别授予；职位不授予全公司范围 | 1.15.0 的 coach product/campaign 和关键词门保持。新能力不能通过把主管改成 owner 实现 |
| dual-review 与人工自审 | 新路径组织审核取认证飞书适配器的人工 task/PASS、timeline、定义/节点和精确审核包。常规可自审；关键必须另一位有资格、同人键可确认且不在贡献集合的审核人 | 旧双组织声明条件只在新受控事务被人工实例证据替换。既有质量计划、population hash、抽样/扩大/缺陷门、owner acceptance、来源有效性均继续检查；不得调用旧函数并伪造两个审核人绕过 |
| 整域替换与来源内合并 | 只将当前 sourceId 的显式差异应用到 base；缺行保留，disable 才下架；继承其他来源与未改条目的精确版本/审批谱系 | 旧写以实际覆盖域推导影响集合，与任何 active 来源相交则整次拒绝。旧回退/CSV SOP/PATCH/下架同样覆盖，不能只挡上传按钮 |

旧读取函数依赖四域权威来源、现有 owner acceptance 和短租约；新 catalog 作为同一 `content_releases.release_id` 的附加内容/谱系，不能替代这些门或创建第二个 current。服务端必须让新旧受控写共同维护既有四域绑定和附加 catalog；旧写继承未触及域的 v2 catalog。不能可靠完成继承或无法推导影响集合的旧写失败关闭。冻结后在产品事务里追加对应约束和最小 ACL，本文的存储表不授权绕过旧发布函数。

## 3. 身份、授权与来源

### 3.1 主体与授权

主体从产品会话解析；renderer 不得传 actor/userId。`principal_id` 对接既有 `backend_identity.subject_bindings.user_id`。tenant/app 是强隔离边界；`identity_scope+person_key` 只在已确认提供方键范围内归一，未知/冲突身份禁止关键独立他审。部门与岗位必须精确映射，命中多个不同角色失败关闭。组织事实成功核验最长 5 分钟；失败不能推进 checked_at/valid_until；禁用或撤权增加代际。历史 facts 追加保存以证明审核当时资格，当前资格另验。policyVersion 是 tenant/app 的整体岗位策略版本，由 role_rules 的写入历史触发器同步推进 policy_versions；每行 policy_version 仍是该条规则的历史版本，两者不可混用。

八个业务动作见 `IntakeAction`。普通坐席只 query。服务赋能师、组长、主管、经理、总监仍须显式范围业务授权。`shopId=null` 是品牌通用范围，不包含任意店；`sourceId=null` 只覆盖同 tenant/app/brand/shop/domain 的全部来源。候选必须有非空登记 sourceId，材料、对象、范围必须同源。角色只给能力上限，business、allocation、delegation 三类记录不能互相当作权限。

总监/经理/主管可在受控 allocation 内分配业务权限；有 delegation 的其他主体可按资格分配，不能据此使用内容能力。仅总监/经理可从 allocation 发出 delegation；业务默认为不可继续转授，本 P2 合同只支持 `may_redelegate=false`；例外须后续合同另行批准。禁止本人或已归一别名自提权，禁止跨范围或超出母资格期限；一个记录一个 action/scope，多选最多 64 项同事务全成全败。根 allocation 由既有受控运维流程登记，不开放自授权 HTTP 接口。

每次授予/撤销/接管保存原 issuer、parent、初次 reason、历史版本并增加受影响主体代际；撤权/接管请求的 reason 写入新版本 last_change_reason（HTTP lastChangeReason），由历史触发器随完整新版本追加；初次版本该字段为 null，后续非空，不得改写初次原因或旧历史；不覆盖历史审核时所需权限快照。撤 delegation 保留下游已发业务权，接管的授权主体/范围不变，只变 steward 及对应版本/变更原因；无接管人保留合法业务权并停止新分配，进入受控运维队列。重复撤销无副作用。DDL 已保存 grant/岗位映射追加历史；产品受控事务须同时校验历史事实与当前事实，更新版本及代际，不能只读取当前 grant 推断过去资格。

### 3.2 来源与词项

来源登记固定 scope，HTTP mapping 更新只追加 template/rule/mapping/structure 版本。文件声明不改变授权。整数 revision 仅同源比较；opaque/unknown 必须人工核对，时间/hash/大小不证明新旧。source-confirmation 独立绑定 candidate/version/digest/source/fileSha256 和确认版本，不参与材料 hash；审批不代替来源核对。

商品/场景 ID 的 scope、kind、meaning_digest 不可就地改义；展示更名追加 display_version。被候选/发布引用的 ID 禁停用；变义新建 ID，经纠正候选迁移。快照读取引用当时显示版本。scope 本身及 source→scope 绑定在首次引用后不可移动；产品事务必须把受控登记/版本守卫与授权一起完成。

## 4. 导入、材料、证据与使用资格

- XLSX 受控对象上传后，API worker 用同版本解析器独立复算；不接受 renderer 的 rows/hash/已审核。原始对象、报告和审核包存于既有受控对象存储；HTTP 仅 objectId，不接受路径/任意 URL。表头、编号、整批错误、公式/宏/外部资源和限额沿 `intake-p1.1`。`IntakePolicy` 对外提供确切值；来源模板 `faq-p1.1`。P2 选中媒体仍明确拒绝，SOP/media 数组为空，不伪造支持或回落 Demo。媒体能力须后续版本。
- 解析状态只含 reading/parsing/validated/failed/cancelled。有效行整批冻成 candidate；阻断错误只出有行列坐标的报告，无半个候选。报告/模板/编号建议须实际重新打开和导入；编号建议不能直接替业务维护人改原文。
- 上传时通过 `IntakeReceive.contributorDeclaration` 明确声明整理责任人、全部实际改稿人并确认；本人制作也须列本人。服务端加入会话上传者、校验同 tenant/app 已确认身份并归一，冻结入 contributors。受控主体选择仅依据调用者目标来源资格，返回同 tenant/app 的已确认主键、展示名、事实版本和有效截止；首次授权不要求接收人已有业务 grant；贡献人不要求内容操作权，已禁用但身份可确认者也能列入。查不到的贡献人须先走身份登记，不能省略。声明变更创建新材料版本。
- 材料按 `IntakeMaterial` 的完整字段以版本化 JCS UTF-8 编码，SHA-256 服务端计算。必须包括全部规范内容、逐项差异与服务器分配版本、稳定业务/问法 ID、选表、模板/规则/映射、来源声明、对象 hash、scope、词项引用、适用时段、媒体、贡献人、风险、base。审批/来源证据 ID、核验时刻、实例/task、readiness、operationId 不进入材料。DB 检查 canonical JSON 与材料一致、精确对象/来源绑定；JCS 规范及完整 schema 仍由 API 独立复算负责，SQL 的 JSON 等价检查不证明 JCS。
- 分类、内部说明、风险提示、附件说明是材料及审核包的一部分。坐席投影仅允许分类和单独风险提示，内部说明不出现在坐席正文；复制只取 answerText。P2 非空附件说明仍阻断导入，不能把说明当作已支持媒体。词项仅可引用同 tenant/app/brand/domain 的品牌通用或当前店铺词项，禁止反向将店铺词项用于品牌通用稿。
- 缺行从不删除；答案与问题独立分版。显式 disable 单稿≥2或同 source 滚动 UTC 24h 累计≥2升关键；risk-p1.1 固定策略，风险不得由客户端下调。不声称防跨来源分拆。过敏命中 title 或 body 时 body 必须同时有“停手”“确认”。实际风险与完整差异由服务器从 base 复算。
- brandNonOverridable 仅品牌范围有权人可设置。显式 sourceId+businessEntryId family 关联决定覆盖；先按当前店、商品/场景交集、时段过滤，再处理通用/店铺覆盖。同级重叠和对抗强制品牌稿阻断；标题相似不自动归并。
- 候选状态只含 awaiting-evidence/ready/publishing/published/cancelled/invalidated。补首次来源/审批证据不变材料；expectedPriorKey=null 明确新建；完整旧键明确修订。解析 job 持久保存接收时映射版本、归一贡献人集合、该原键和成功结果键，成功结果必须同映射/主体/贡献集合，复算成功后锁内 CAS 旧键/可修订状态，原子废旧并创建同 candidateId 下一版本；失败保留旧稿。publishing/unknown 先核对结果，published/cancelled/invalidated 不可修订。换实例只增 evidenceVersion。待证据不占用旧 import batch。只有 ready 发布尝试关联短期 batch；unknown 保留文件/键/引用，不放出第二个在途尝试。
- 创建飞书实例前持久化 UUID、固定审核包 object/hash、定义/node 和 reviewRequestId。认证适配器校验人工 PASS、候选绑定、完整表单及附件实际字节 hash；fileCode 不等于 URL 或内容 hash。关键稿审核人排除贡献人及同人别名，核验审核当时及提交当下资格。remote JSON/worker 自述/表内已审核不能证明通过；客户端不能写审批事实。
- approval facts 以实例去重，核验成功最长 5 分钟。失败不续期，事件丢失也必须到点停止。撤销事务同时追加代际和全部受影响 release_revocations，包括继承内容与历史 SOP 引用。事后离职不等于实例撤回，已有内容按其治理规则处理。
- 新签/续签使用资格取组织事实、grant、所有谱系审批事实、内容时效、既有 lease 上限中最早截止。P2 只签当前 release，shop 必选/单店可唯一解析；不开放历史 SOP 使用入口。Main 是 Query 与独立 SOP 窗失效所有者，失效清正文/禁复制/推进；普通新版本通知不清空有效结果。复制只表示已复制。

## 5. 事务义务、失败与兼容

持久层已防止当前身份/审批事实指针及代际倒退、消费票据复活、操作键改写；文件与解析任务绑定 source/actor，审核包绑定 hash/purpose/tenant/app，多来源回退包不伪挂单一 source，租约绑定 principal/user/release。贡献人表是冻结材料的只读派生视图；sourceClaim.fileSha256 与对象列有同一性约束。完整 JCS、历史审核资格、受影响来源全量集合与提交时事实仍属下列产品事务义务。

mode 由 API 内部受控配置/运维流程唯一维护，本次不开放 renderer 的模式写接口；真实 active 按 P4 批准，不能因缺少业务 HTTP 写接口而临时直改数据库。

以下是产品 intake 后必须实现并通过双会话测试的原子边界；本候选 DDL 没有把它们实现成可调用发布函数。所有写采用已有 `backend_review.lock_content()` 首锁，再按稳定 ID 顺序取 scope/principal/source/candidate/evidence/current 行；旧发布 try-lock 按原位置保留。不得逆序加锁。远程核验、文件解析在锁外；事务隔离 READ COMMITTED，锁等待建议 2s、statement/事务预算 5s，均小于票据 60s。提交前用服务器当前时钟重验有效期，不用事务起点 now() 宽限排队。

| 事务 | 锁内重验与写入 | 失败恢复 |
| --- | --- | --- |
| 分配/撤权/接管 | 双主体事实/岗位/母授权当前版本、期限、同人键、scope；写整批与历史审计，增加代际 | 整批回滚；无 steward 不扩大权限 |
| 上传/admission/冻结 | 同租户对象与在途候选预算原子计数；actor 10/source 100/tenant staging 1GiB；对象归属、映射、base 与授权重验 | 超限拒绝新任务，保留既有稿及查询；清理按既有 retention dry-run+明确删除流程 |
| 补证/换实例 | 精确 candidate/version/digest、source/object、包/人工节点与资格；独立 evidenceVersion 和代际 CAS | 首次补证不循环重算材料；旧票据失效 |
| 发布提交 | 先查永久 candidate-version→release；同 operation/payload 重放、异 payload 拒绝；锁内核对 base/current、实际影响模式、当前发布者/审核者权限、来源/候选/审批代际、全部证据版本及未消费未到期票据；既有质量/来源/owner acceptance 门继续有效 | base 改变需新候选重审；票据过期且明确未提交才重签；禁止锁内远程调用 |
| 发布写集合 | 在一个事务写旧 release/four-domain bindings、FAQ 来源内 merge、统一空 SOP/media、词项与逐条谱系、current、四库差异公告、candidate published、永久 publication、幂等回执并消费票据 | 任一失败全回滚；24h 缓存过期不删除 publication；丢响应按原键核对 |
| 取消 | 精确候选及尝试，与发布同锁序；取消赢则无 release，提交赢返回 ALREADY_PUBLISHED；不碰同人其他候选 | unknown 保持核对，不假报取消成功 |
| 回退 | immutable rollback_plan 绑定 target/base/全部影响 source 与 digest；独立人工审核包；全量权限与所有谱系仍有效；写新 release 和同一 publications 永久回执 | 无全量权限走单来源正常纠正候选；撤销/失效内容不得复活 |
| mode/旧写 | mode 唯一 API 配置 owner；启用与旧写共锁并核 base/modeVersion；旧整域写按至少整个绑定域的全部来源计算影响 | active 相交或无法推导拒绝整次；不同域只有证明无交集且继承 v2 catalog 才允许 |
| 使用资格/审批撤销 | current、组织/grant/全部谱系事实批量取；同锁序使签发与撤销串行；lease、scope、shop、principal、代际与最早截止精确绑定 | 撤销先赢不得新签；签发先赢撤销增代际并失效；失败不续命 |

路径/body 中 candidateId/version/key 不一致一律 VALIDATION，不能任选一个。所有 mutation 使用原 operationId+主体+动作命名空间和 payload digest；GET /operations/{operationId} 必填 action 以唯一选中发布、取消或回退结果；scope 与真正主体来自会话/登记事实。具体资源不存在与无权均返回同一脱敏 NOT_FOUND；未认证为 401，与资源存在性无关的全局能力/策略拒绝才使用 403；内部 diagnosticId 保留原因。错误沿既有 `error.code/message/details.reason` 外壳，reason→动作在 OpenAPI 限定：修文件、补证、刷新事实、重核候选、查询原操作结果。parser 错误不能显示“未连接飞书”。

全目录 rollback 的人工审批针对独立 rollbackPlanId/impactDigest，不能套一个单来源候选的审批。GET review 只读已核验事实，不续期；POST review/refresh 按原计划、impactDigest 和证据版本重核原实例，不新建实例或变更材料，认证失败不延长有效期。rollback 的稳定操作结果还须由产品 `/operations` 消费器区分动作类型；不得把发布结果和取消/回退混用。服务端不得向 renderer 返回一次票据或提供方凭据。
